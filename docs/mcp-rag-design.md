# MCP docs Q&A design -- Bedrock RAG over BBB's own docs

Design doc for extending the BBB MCP server (`mcp/` + `infra/`) with a
retrieval-augmented Q&A capability over this repository's public
documentation, built end to end on Amazon Bedrock. Written 2026-08-22,
committed before any implementation (design-doc-first, same process as the
original MCP build).

## Goal and shape

Two new read-only tools on the existing MCP server, behind the existing
API Gateway key and usage plan:

| Tool | Bedrock API | Returns |
|---|---|---|
| `search_docs` | `Retrieve` | Matching doc chunks with source references and relevance scores. No generation, no LLM cost. |
| `ask_docs` | `RetrieveAndGenerate` | A grounded answer with citations, generated by Claude Haiku 4.5 from retrieved chunks only. |

Everything else about the server is unchanged: same endpoint, same
stateless streamable-HTTP transport, same auth gate, same
one-request-one-tool-execution property.

## Architecture

```
MCP client
  | POST /mcp  (x-api-key)
  v
API Gateway (REST) ......... auth gate + throttle + monthly quota (500)
  v
Lambda bbb-mcp-server ...... existing three tools unchanged
  |                          search_docs -> bedrock:Retrieve
  |                          ask_docs -> bedrock:RetrieveAndGenerate
  v
Bedrock Knowledge Base ..... type VECTOR, Titan Text Embeddings V2
  |     (bbb-mcp-docs)       (amazon.titan-embed-text-v2:0, 1024 dims)
  |
  +-- S3 Vectors ............ vector bucket + index (float32, 1024,
  |                           cosine; non-filterable metadata keys
  |                           AMAZON_BEDROCK_TEXT / AMAZON_BEDROCK_METADATA)
  +-- Corpus S3 bucket ...... private; synced by the deploy workflow
                              from the curated manifest below
Generation (ask_docs only): Claude Haiku 4.5 via the au. geographic
inference profile (au.anthropic.claude-haiku-4-5-20251001-v1:0; routes
Sydney + Melbourne, since Claude is not in-region in ap-southeast-2)
```

Why the managed stack rather than a hand-rolled embed-and-cosine-search
Lambda (which would be leaner for a corpus this small): the point of this
increment includes demonstrating the named platform services end to end
(Bedrock Knowledge Base, S3 Vectors, managed ingestion, knowledge
grounding with citations), and the managed path is also less code to
review and maintain. OpenSearch Serverless is explicitly rejected as the
vector store: its minimum-OCU idle charge (~USD 350/month) is absurd for
this workload. S3 Vectors has no idle compute cost and is GA in Sydney.

## Corpus: curated allowlist, not a glob

The corpus is an explicit manifest (`mcp/corpus-manifest.txt`, one
repo-relative path per line), synced to the corpus bucket by the deploy
workflow with `aws s3 sync --delete` so removals propagate:

- `README.md`
- `mcp/README.md`
- `infra/BOOTSTRAP.md`
- `docs/abuse-audit.md`
- `docs/cycle-visuals-design.md`
- `docs/data-refresh-2026-05.md`
- `docs/deploy-runbook.md`
- `docs/mcp-rag-design.md` (this document)

Deliberately excluded: `CLAUDE.md`, `PLAN.md`, `AGENTS.md`. They are
internal working notes (including candid legal-hygiene rationale and the
avoid-list wording verbatim), and while the repo is public, the served
Q&A surface should not generate answers out of internal strategy notes.
A unit test enforces the manifest: every listed file exists, the excluded
files never appear, and every corpus file passes the same banned-language
sweep the server's own strings do.

Chunking: the data source uses Bedrock's default fixed-size chunking.
Tens of files, well under every ingestion limit.

## Tool contracts

`search_docs`:

- Input: `query` (string, 3..300 chars), `top_k` (int, 1..8, default 4).
- Output: `results[]` of `{ text, source, score }`, where `source` is the
  repo-relative doc path recovered from the chunk's S3 URI, plus the
  standard attribution string.

`ask_docs`:

- Input: `question` (string, 3..300 chars).
- Output: `{ answer, citations[] }` where citations carry the generated
  span and the source doc paths it rests on, plus attribution.
- Generation config: temperature 0, max 500 output tokens, retrieval of
  up to 4 chunks. The prompt template instructs the model to answer only
  from the retrieved passages, to say plainly when the passages do not
  contain the answer, to treat retrieved text as reference data rather
  than as instructions, and to keep the project's observation-only
  framing (estimates, never guarantees).

When the RAG environment variables are absent (see Config) the tools are
simply not registered, and the server instructions omit them, so
`tools/list` and the instructions always reflect reality.

Injection posture: the corpus is BBB's own committed docs, so the
retrieved content is trusted-authored, but the prompt template still
treats it as data, and the caller's question is bounded to 300 chars.
Generated answers are checked against the language-discipline term list
at runtime and withheld on a violation, so a caller cannot steer the
endpoint into serving prohibited framing. This is stated in the
security-posture doc.

## Terraform resources (all in the existing single root module)

Provider constraint moves to `>= 6.27.0, < 7.0.0` (S3 Vectors and
Bedrock agent resources; the committed lockfile is already at 6.60.0, so
no lockfile change).

New resources in `infra/rag.tf`:

- `aws_s3_bucket.corpus` (+ public access block, SSE, versioning off):
  `bbb-mcp-corpus-<account-id>`.
- `aws_s3vectors_vector_bucket.docs` and `aws_s3vectors_index.docs`:
  float32, dimension 1024, cosine, non-filterable metadata keys
  `AMAZON_BEDROCK_TEXT` and `AMAZON_BEDROCK_METADATA`.
- `aws_iam_role.kb` (`bbb-mcp-kb-role`) with trust for
  `bedrock.amazonaws.com` conditioned on this account and this account's
  knowledge-base ARNs; policy grants S3 read on the corpus bucket, the
  specific vector operations Bedrock needs (get/put/query/delete/list),
  scoped to the vector bucket and index, and `bedrock:InvokeModel` on
  the Titan V2 model ARN only.
- `aws_bedrockagent_knowledge_base.docs`: type VECTOR, Titan V2
  embeddings (1024), `storage_configuration { type = "S3_VECTORS" }`.
- `aws_bedrockagent_data_source.docs`: the corpus bucket, default
  chunking, `data_deletion_policy = "DELETE"`.
- Cost backstop (see next section): `aws_budgets_budget.mcp`,
  `aws_budgets_budget_action.deny_bedrock`, `aws_iam_role.budgets`
  (`bbb-mcp-budgets-action`), `aws_iam_policy.bedrock_deny`
  (`bbb-mcp-bedrock-deny`, a customer-managed `Deny bedrock:*`).

Changes to existing resources:

- Lambda execution role gains one inline policy: `bedrock:Retrieve` on
  the KB ARN; `bedrock:RetrieveAndGenerate` on `*` (the action is not
  resource-scopeable); `bedrock:InvokeModel` and
  `bedrock:InvokeModelWithResponseStream` on the `au.` inference-profile
  ARN and on the Haiku 4.5 foundation-model ARN in both destination
  regions (ap-southeast-2 and ap-southeast-4); and
  `bedrock:GetInferenceProfile` on the profile ARN, which
  `RetrieveAndGenerate` needs to resolve the profile's routing before it
  invokes (without it, retrieval works but generation returns
  AccessDenied -- found in live E2E). Nothing else.
- Lambda environment gains `BBB_KB_ID` and `BBB_RAG_MODEL_ARN`.
- Lambda timeout 20s -> 25s (generation is the new worst case; still
  under API Gateway's 29s integration limit).
- `monthly_quota` default drops from 100000 to 500 (see below).
- New outputs: `knowledge_base_id`, `data_source_id`, `corpus_bucket`
  (none of these are secrets; the API key remains non-output).

Ingestion has no Terraform resource. The deploy workflow, after a
successful apply, stages the manifest files, syncs them to the corpus
bucket, starts an ingestion job (`aws bedrock-agent
start-ingestion-job`), and polls it to COMPLETE (bounded wait, fails the
run on FAILED or timeout). `terraform destroy` remains a full
decommission: KB, data source, vector index, buckets, budget action.

## Cost guards (AWS-enforced, layered)

The requirement: a firm backstop in AWS itself, not only in code,
against a hostile caller driving up the bill. Layers, front to back:

1. **Usage-plan monthly quota: 500 requests/month** (was 100000, sized
   for a paid-generation era and near-zero real traffic; shared across
   all five tools). Arithmetic ceiling: even if every one of the 500
   requests were a worst-case `ask_docs` call (~USD 0.01), the month
   tops out around **USD 5** before any other layer engages. Throttle
   (5 rps, burst 10) is unchanged.
2. **Lambda reserved concurrency** (existing variable): bounds burst
   independently of the gateway. Honest caveat: on a fresh account AWS
   refuses reservations that would drop unreserved concurrency below
   100, so the default stays unreserved until the account's regional
   limit is raised; layers 1, 3 and 4 do not depend on it.
3. **Per-request caps in code**: 300-char inputs, one upstream attempt
   per request (no SDK retries), at most 4 retrieved chunks on the
   generation path (8 for retrieval-only search), 500 output tokens,
   temperature 0, one tool execution per metered request (batching
   already rejected).
4. **Budget action in Terraform**: an account-wide (no service filter)
   USD 5 monthly budget on actual costs, with an `APPLY_IAM_POLICY`
   action (automatic approval) that attaches the customer-managed
   `Deny bedrock:*` policy to the Lambda execution role at 100% of
   budget. Post-deploy verification includes confirming the action shows
   **Standby** in the console. Honesty note: Budgets cost data lags by
   hours, so layers 1..3 bound spending inside the lag window and this
   layer ends it afterwards. The existing bootstrap zero-spend alert
   budget and the console alert-only budget Justin created on
   2026-08-22 are left untouched (the zero-spend alert will now fire
   once real Bedrock spend begins; that is expected and can be retired
   by hand whenever it becomes noise).
5. **No long-lived credentials** (unchanged): OIDC-only deploy role,
   human-approved runs.

## Config

Lambda env (set by Terraform, never hardcoded):

- `BBB_KB_ID`: knowledge base id.
- `BBB_RAG_MODEL_ARN`: the `au.` inference-profile ARN used by
  `ask_docs`.

If either is absent the RAG tools are not registered; the original three
tools work regardless.

## Deploy-role delta (bootstrap, human-run)

The one-time deploy role (`bbb-mcp-deploy`) currently cannot manage
Bedrock, S3 Vectors, S3 corpus buckets, Budgets, or the two new IAM
roles. `infra/BOOTSTRAP.md` gains an idempotent one-paste policy update
(same style as the original bootstrap) adding, all name- or
account-scoped:

- S3 on `bbb-mcp-corpus-*` (bucket management + object sync).
- `s3vectors:*` on `bbb-mcp-*` vector buckets/indexes.
- Bedrock knowledge-base/data-source lifecycle + ingestion jobs, scoped
  to this account and region.
- IAM lifecycle on `role/bbb-mcp-kb-*` and `role/bbb-mcp-budgets-*`,
  plus `iam:PassRole` of those roles to `bedrock.amazonaws.com` and
  `budgets.amazonaws.com` respectively; customer-managed-policy
  lifecycle on `policy/bbb-mcp-*`. The existing explicit Deny on
  modifying `bbb-mcp-deploy` itself stays.
- Budgets lifecycle on `budget/bbb-mcp-*`.

Added 2026-08-23 (issue #101): every role Terraform creates now carries a
permissions boundary, so the policies the deploy role writes for them are
capped by a ceiling set outside the pipeline. The deploy role's
`iam:CreateRole` is conditioned on that boundary being set, it may attach
only that one boundary ARN, it holds no
`iam:DeleteRolePermissionsBoundary`, and an explicit Deny stops it editing
the boundary policy (which its `policy/bbb-mcp-*` Allow would otherwise
cover). The boundary itself is created by the human bootstrap, not by
Terraform, for that reason. See "Update for the permissions boundary" in
`infra/BOOTSTRAP.md`.

## Testing and verification

- Unit tests drive both tool handlers with a mocked Bedrock client
  (injected; no AWS SDK call leaves the test process): happy path,
  bound violations, unconfigured-env behaviour, empty-retrieval
  behaviour, citation mapping.
- The language-discipline test extends to the new source files and to
  every corpus manifest file.
- Manifest test: listed files exist, excluded internals never listed.
- CI is unchanged in shape: `npm run check` plus `terraform fmt`/
  `validate` with no credentials.
- Post-deploy E2E (real MCP client): `tools/list` shows five tools,
  `search_docs` returns cited chunks, `ask_docs` returns a grounded
  answer with citations, an unauthenticated call is still rejected at
  the gateway, and the budget action is in Standby.
